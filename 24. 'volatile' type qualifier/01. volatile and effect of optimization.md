# The `volatile` Type Qualifier in C:
- **Type qualifiers** are keywords applied to the data types to change how the compiler treats them and optimize them.

- There are two important type qualifiers:
  1. **const**
  2. **volatile**

## 1. What is `volatile`?

- `volatile` is a **type qualifier** in C, used with variables.

- It tells the compiler **not to apply any optimization** on the variable operation.

- A **variable operation** means either a **read** or a **write**.

- It signals the compiler that the variable's value **may change at any time**, with or without the programmer's involvement.

- The compiler therefore stops optimizing reads and writes of `volatile` variables.

- This is very helpful in **embedded systems code** for avoiding bugs.

## 2. Volatile STM32 project

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	uint8_t Data01;
	uint8_t Data02;

	Data01 = 50;

	/* Data01 is moved to Data02 */
	Data02 = Data01;

	/* Data01 is moved again to Data02 (redundant statement) */
	Data02 = Data01;

	for(;;);
}
```

- The second `Data02 = Data01;` is a **redundant statement**.
- A smart compiler would generate instructions for only one of them, which is one kind of optimization (fewer instructions).

## 3. Observations at Different Optimization Levels

### 3.1. -O0 (no optimization)

- Disassembly shows a **store** of `50` into `Data01`.
```assembly
    Data01 = 50;
movs R3, #50;
strb r3, [r7, #7]
```

- For each `Data02 = Data01`, it generates a **load** (memory to register `r3`) followed by a **store** (into `Data02`).
```assembely
    Data02 = Data01;
ldrb r3, [r7, #7]
strb r3, [r7, #6]
```

- The redundant copy is **not removed**: all instructions are generated, even the unnecessary ones.
```assembely
    Data02 = Data01;
ldrb r3, [r7, #7]
strb r3, [r7, #6]
```

### 3.2. -O1 (without `volatile`)

- The compiler **removes all the instructions** for these statements in `main`.
- Reasons:
  1. The repeated `Data02 = Data01` is redundant.
  2. `Data01` and `Data02` are **unused variables**: they are created and initialized but never used for any operation, argument passing or result.
- Only the instruction for the `for` loop remains.

## 4. Fix: Use `volatile`

```c
volatile uint8_t Data01 = 50;
volatile uint8_t Data02;
            or
uint8_t volatile Data01 = 50;
uint8_t volatile Data02;
```

- The `volatile` keyword is placed **before or after the type specifier**, so both variables are volatile `uint8_t`.
- **At -O1:** instructions for the `Data01` and `Data02` operations are generated again. Debugging shows `Data01 = 50` and `Data02 = 50`.
- **At -O3 (very aggressive optimization):** the operations are **still not optimized away**.

## 5. Key Takeaways

1. `volatile` forces the compiler **not to optimize** reads and writes of a variable.
2. This holds **even at high optimization levels** such as -O1 and -O3.
3. Without `volatile`, the compiler may delete code it sees as redundant or unused.
4. `volatile` matters most in embedded code, where values can change outside the program's normal flow.
